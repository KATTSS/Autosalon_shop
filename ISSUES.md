# Расхождения спецификации и реализации
 Основание: требования пунктов 1–6 [DOCS.md](DOCS.md).
Все перечисленные дефекты открыты. В этом проходе исходники приложения не менялись.

| ID | Требование | Расхождение | Подтверждение |
|---|---|---|---|
| ISSUE-001 | UR-04, UC-06 | Сервер разрешает оформить заказ без точки самовывоза | Strict xfail |
| ISSUE-002 | UR-05, UC-08 | История не показывает итоговую сумму после скидки | Strict xfail |
| ISSUE-003 | NFR-02 | PostgreSQL в Compose не используется приложением | Проверка активных настроек и кода |
| ISSUE-004 | BG-05, раздел 1.2 | При текущем локальном запуске media недоступны по HTTP | Strict xfail |
| ISSUE-005 | NFR-06 | При сборке Docker ошибка collectstatic скрывается | Проверка Dockerfile и настроек |

## ISSUE-001

**Воспроизведение:** войти как покупатель, добавить товар, отправить POST
`/checkout/` без поля `pickup_point`.

**Ожидается:** отклонение оформления, отсутствие Sale, сохранение корзины.
**Фактически:** создаётся Sale с `pickup_point=None`, корзина очищается.

**Причина:** `CheckoutView.post` передаёт отсутствующее значение в допускающий
NULL внешний ключ и не проверяет обязательность выбора. HTML-ограничение формы
не заменяет проверку сервера.

**Проверка:** `test_checkout_requires_pickup_point` в
`core/tests/test_requirements_gaps.py`. Требование сохранено, а не ослаблено.

## ISSUE-002

**Воспроизведение:** оформить заказ на 200 руб. со скидкой 10%, открыть
`/profile/orders/`.

**Ожидается:** в истории видны исходная сумма 200 руб. и итоговая 180 руб.
**Фактически:** HTML содержит исходную сумму и процент скидки, но не выводит
`discounted_total_amount`; само значение 180 корректно сохранено в БД.

**Причина:** `core/templates/core/order_history.html` не выводит итоговую сумму.
**Проверка:** `test_order_history_displays_discounted_total` в
`core/tests/test_requirements_gaps.py` проверяет именно HTML.

## ISSUE-003

**Воспроизведение:** проверить `DATABASES['default']['ENGINE']` при текущих
настройках или прочитать активный блок `autosalon/settings.py`.

**Ожидается:** приложение в производственной конфигурации подключается к
PostgreSQL; измерение 100 одновременных сессий проводится на этой СУБД.
**Фактически:** активна SQLite. Обработка `DATABASE_URL`/`DB_*` закомментирована;
`docker-compose.yml` запускает PostgreSQL, но web его не использует.

README исправлен и теперь описывает фактическую конфигурацию. Производственная
PostgreSQL и нагрузка остаются неподтверждёнными; фиксация дефекта не заменяет
их проверку.

## ISSUE-004

**Воспроизведение:** при текущем `DEBUG=False` создать график статистики,
запросить `/media/charts/popularity.png` через Django-приложение.

**Ожидается:** файл доступен по указанному на странице адресу, график видим.
**Фактически:** HTTP 404, хотя файл создан. То же ограничение затрагивает
загруженные изображения.

**Причина:** media-маршруты в `autosalon/urls.py` добавляются только при DEBUG;
отдельный веб-сервер для media в репозитории не настроен. Это дефект текущего
локального/контейнерного способа запуска, а не утверждение о любом внешнем хостинге.

**Проверка:** `test_generated_chart_is_available_via_its_media_url` в
`core/tests/test_requirements_gaps.py`. Само создание PNG проверяется обычным
интеграционным тестом статистики.

## ISSUE-005

**Воспроизведение по конфигурации:** Dockerfile запускает `collectstatic` на
стадии сборки. `.dockerignore` исключает `.env`; SECRET_KEY не задан инструкцией
ENV/ARG Dockerfile. Настройки требуют SECRET_KEY при импорте.

**Ожидается:** static собираются успешно или ошибка сборки явно останавливает
создание неполного образа.
**Фактически по исходникам:** команда завершится ошибкой отсутствующего ключа,
но `|| true` скрывает её. `--env-file` при запуске контейнера не исправляет уже
прошедшую стадию сборки. Дополнительно Gunicorn сам не раздаёт static/media.

**Подтверждение:** сопоставление Dockerfile, `.dockerignore` и
`autosalon/settings.py`; реальная сборка Docker не выполнялась. Нужны успешная
сборка и HTTP-проверка static/media после настройки способа раздачи файлов.

## Проверки, которые ещё не выполнены

- NFR-01: p95 времени каталога при заданной нагрузке не измерен.
- NFR-02: 100 одновременных сессий на PostgreSQL не проверены; см. ISSUE-003.
- NFR-06: сборка и запуск Docker на Linux и Windows не проверены; см. ISSUE-005.

Это пробелы в верификации, а не доказанные нарушения численных показателей.
`xfail(strict=True)` отмечает три воспроизводимых нарушения требований;
после исправления неожиданное прохождение теста потребует снять отметку.
